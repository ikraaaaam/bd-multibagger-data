System overview

Two tracks, one screener.

A scheduled scraping pipeline keeps data fresh without a server. The app itself stays a static, storage-backed artifact. Everything downstream — scoring, technicals, AI reasoning — reads from the same cached dataset.

Agent architecture

Separation of concerns, not a router of vendors.

Multibagg AI's public writeups describe a multi-LLM router across GPT-4o and Gemini — treat the specific vendor claims as unverified, but the underlying pattern is sound. For single-user scale, the win isn't which model answers, it's keeping deterministic math out of the LLM's hands and giving each reasoning task its own scoped context.

A true Medallion-style edge isn't LLM agents at all — it's thousands of small deterministic signals (momentum, volume, volatility, mean-reversion) combined statistically. The agent layer's real job is narrating what that engine finds, not generating the edge itself.

Coverage universe & cost control

Small, bounded, cached — that's how $0 stays $0.

The screener stays full-market — DSEX/DSES, deterministic, free, no token cost. The AI agent layer is deliberately narrowed to a curated watchlist, because that's the only place free-tier token limits can actually bite.

Total AI-covered universe: ~55–60 stocks, out of 300+ listed on DSE. Everything outside this stays visible in the screener but never triggers an agent call unless promoted into the watchlist.

Rule 01 — Cache always
Every AI output → window.storage
Timestamped. Reload or re-view reads cache, never re-calls the model.
Rule 02 — Regenerate on change
Score moves ±5, or 24h passed
Whichever comes first. Most stocks need zero fresh calls most days.
Rule 03 — Lazy, not eager
Generate on open, one at a time
Never pre-generate insights for all 55–60 stocks on page load.
Rule 04 — Graceful degradation
Rate limit hit → show last cache
Small "updating…" note, never a broken screen or hard error.
Data model

What lives where.

Two data classes: pipeline-fed (prices, index membership — refreshed automatically) and user-owned (portfolio, SIP, fundamentals you verify — stored personally, never shared).

// pipeline-fed — refreshed by GitHub Actions, fetched read-only
index:dsex        { updated_at, constituents: [ticker, ...] }
index:dses        { updated_at, constituents: [ticker, ...] }   // Shariah gate
prices:{ticker}   { last_price, change_pct, volume, updated_at }
history:{ticker} { entries: [{date, open, high, low, close, volume}] }

// user-owned — window.storage, personal scope
stocks:{ticker}   { roe, de_ratio, eps_history[], nocfps, cap_class, sector, verified_at }
portfolio:holdings { {ticker}: {qty, avg_cost, target_allocation} }
sip:schedule      { monthly_budget, step_up_rate, carry_forward: {ticker: amount} }
sip:history       [ {date, ticker, qty, price, amount} ]
settings:profile  { freedom_target, horizon_years, risk_notes }
Build plan

Six phases, each independently usable.

Every phase ships something you can actually use with real data before the next one starts — no phase depends on unfinished work from a later phase.

01

Data Pipeline & Index Foundation

Goal — fresh DSEX/DSES data flowing, free, on a schedule

Stand up the scraping pipeline before touching the UI. This is the foundation everything else reads from, so it's proven first, in isolation.

bdshare (Python) GitHub Actions cron raw.githubusercontent.com EOD CSV fallback
  • Python scraper script using bdshare, pulling DSEX + DSES constituent lists and live prices
  • GitHub Actions workflow: runs every 10min during 10:00–14:30 BDT, Sun–Thu; separate daily EOD job at 15:30
  • JSON output committed to repo, fetchable free via raw.githubusercontent.com
  • Staleness check — flags data older than expected instead of silently serving old numbers
02

Index Screener Core

Goal — browse DSEX or DSES, filter by fundamentals, see a Health Score

The first real screen. Pick an index, apply Buffett/Damani-style filters, and get a ranked, scored list — this alone is already a usable daily tool.

React artifact Tailwind window.storage cache
  • Index selector: DSEX (all) / DSES (Shariah-filtered)
  • Fundamental filters — ROE, D/E, EPS growth trend, NOCFPS
  • Health Score engine: 30% profitability, 25% balance sheet, 20% earnings consistency, 15% cash generation, 10% sector-cycle bonus
  • TradingView-tier UI — customizable/reorderable columns, saved filter presets, dense sortable table with keyboard row navigation
  • Heatmap view — color-coded by Health Score or % change, not just a list
  • Inline sparklines per row — 30-day price trend at a glance, no click-through needed
03

Stock Detail & Technicals

Goal — one page per stock, fundamentals and price action side by side

Click through from the screener into a full profile — this is where technical and fundamental views finally sit together instead of living in separate tools.

Recharts history:{ticker} feed
  • Candlestick chart from the history feed
  • RSI, MACD, Bollinger Bands, moving averages overlay toggles
  • Quant Signal Engine — momentum (ROC, MACD histogram trend, MA crossovers), volume (spike vs 20/50-day avg, OBV, price-volume divergence), volatility (ATR, BB width), mean-reversion (%B, z-score)
  • Trading Signal Score — separate from the long-term Health Score; answers "is this stock doing something unusual right now"
  • Fundamental panel — Health Score breakdown, IBSL/DSES badge, sector tag
  • "Add to portfolio" / "Add to SIP" actions launch from here
04

Portfolio & SIP Tracker

Goal — your actual holdings, carry-forward logic, wealth ledger, in the app

Migrates your existing manual wealth-ledger logic into the product itself, including the carry-forward handling for stocks priced above your monthly per-stock budget.

portfolio:holdings sip:schedule / sip:history
  • Holdings view — qty, avg cost, current value, allocation vs target
  • Monthly SIP calculator — whole-share purchase logic against live price
  • Carry-forward tracker for high-priced stocks (e.g. Berger, Marico-style cases)
  • Step-up SIP support and wealth ledger auto-populated from executed buys
05

Multi-Agent AI Layer

Goal — specialized agents for both time horizons, math never left to the LLM

Five roles, not one do-everything prompt: an Orchestrator that routes by intent and time horizon, News, Research, Technical/Quant, and Risk agents. All run on a single Claude model — a multi-vendor router is deliberately deferred until real usage volume justifies the added complexity.

Claude API (fetch, no key needed) single-model, multi-agent grounded prompting
  • Orchestrator — routes by intent and time horizon: long-term question → Research Agent, short-term/momentum question → Technical Agent
  • News Agent — summarizes recent corporate announcements / DSE news for a ticker, separate context window from analysis
  • Research Agent — grounded long-term fundamental narrative from stored data only, no invented numbers
  • Technical/Quant Agent — narrates what the Quant Signal Engine found in plain language: momentum breakouts, volume anomalies, mean-reversion setups
  • Risk Agent — volatility-adjusted position sizing context, so momentum signals come with a sense of scale, not just direction
  • Quant Signal Engine — not an agent at all: momentum, volume, volatility, mean-reversion stay pure deterministic code, LLM only narrates the result
  • Scoped to the ~55–60 stock watchlist — DS30 + curated mid/small-cap tiers; cached in window.storage, regenerated only on ±5 score change or 24h staleness
  • Every AI output carries a visible "not financial advice, verify independently" disclaimer

    Paper Trading Engine

    Goal — test the Quant Signal Engine with virtual money before real money

    A full simulated trading account, reusing the Portfolio module's data shape under a separate paper: storage prefix. One honest constraint set upfront: fills simulate against the latest scraped price (~10min interval), not a live tick-by-tick order book — the UI says so plainly rather than pretending otherwise.

    Webull-style mode indicator market + limit orders equity curve
    • Persistent "PAPER TRADING" banner — Webull-style: a fixed, impossible-to-miss mode strip (amber/black diagonal pattern) across the entire trading UI whenever in paper mode, plus a colored account-switcher so real vs. paper is never ambiguous mid-session
    • Virtual account — configurable starting cash, tracked entirely separate from real portfolio data
    • Order types — market (fills at latest cached price) and limit (fills next time scraped price crosses the limit) — scoped honestly to what a 10-min feed supports
    • Position & P&L tracking — realized/unrealized, per-trade and portfolio-wide
    • Performance analytics — win rate, avg win/loss, max drawdown, equity curve chart
    • Trade journal — a note per trade, so reasoning can be checked against outcome later
    • Feeds directly off the Quant Signal Engine — a trading idea from a momentum/volume signal can be paper-tested in one click before ever touching the real Portfolio module
Trading UI — real and paper, one shared bar

Same premium surface, two modes, zero ambiguity.

Real trading isn't in the app's execution path yet — DSE has no retail order-routing API for a solo founder to plug into — but the stock-detail and screener surfaces are built to the same TradingView/IBKR-class bar either way, since that's where both real and paper decisions actually get made.
